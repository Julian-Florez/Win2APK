Win2APK / manual operativo

Empaquetar una carpeta Windows para Android

Selecciona una carpeta que ya contenga la aplicación o el juego, define su ejecutable, icono e identidad Android, genera el App Bundle y realiza la instalación con bundletool.

Alcance: aplicaciones y juegos distribuidos como una carpeta completa.

Ejemplo: Cuphead sirve para mostrar valores reales. No limita el procedimiento a ese juego.

Resultado: una aplicación Android que ejecuta el programa de Windows mediante un entorno de compatibilidad. No es una conversión a código Android nativo.

Fecha: 2026-09-19. Describe el prototipo disponible en el repositorio.

01 / Entrada

Empieza con la carpeta completa, no con el instalador

Win2APK necesita el directorio final de la aplicación. Allí deben estar el archivo .exe, sus bibliotecas, recursos y subcarpetas.

La carpeta adecuada

  • Contiene el ejecutable que debe abrirse.
  • Conserva la estructura relativa de todos los archivos.
  • Incluye dependencias privadas que la aplicación espera junto al ejecutable.
  • Proviene de una copia que puedes usar y distribuir legalmente.

Lo que no debes seleccionar

  • Un setup.exe que todavía debe instalar el programa.
  • Solo el ejecutable, si el programa utiliza archivos vecinos.
  • Una carpeta con DRM, anticheat o controladores de Windows que el entorno no soporte.
  • Datos cuyos permisos de distribución no tienes.
Compatibilidad no significa universalidad. El sistema empaqueta una carpeta y prepara Winlator para ejecutarla. Cada aplicación puede exigir otra versión de Wine, componentes de Windows, argumentos, controles o configuración gráfica. Empaquetar correctamente no garantiza que cualquier ejecutable funcione.

Herramientas necesarias

  • El repositorio Win2APK con el subrepositorio winlator.
  • JDK 17, Android SDK, ADB y Gradle Wrapper.
  • tools/bundletool-all-1.18.3.jar, incluido en este repositorio.
  • Un dispositivo Android con depuración USB o depuración inalámbrica autorizada.
  • Espacio libre para construir el AAB, generar el conjunto APKS e instalar los datos.

03 / Preparación

Coloca la carpeta dentro de uno o más asset packs

Los datos grandes no deben añadirse al APK base. Win2APK los distribuye como módulos Play Asset Delivery y conserva sus rutas relativas.

  1. Verifica la raíz y el ejecutable

    La raíz del payload debe corresponder al contenido que terminará en C:\NombreDeCarpeta. Si el ejecutable está en una subcarpeta, registra la ruta relativa completa en app.executable.

    MiAplicacion/
├── MiAplicacion.exe
├── datos/
├── plugins/
└── configuracion.ini

  2. Cuenta archivos y bytes

    Estos valores permiten que Android valide que el movimiento terminó completo. Sustituye la ruta por la carpeta real.

    GAME_DIR="/ruta/a/MiAplicacion"

find "$GAME_DIR" -type f | wc -l
find "$GAME_DIR" -type f -printf '%s\n' \
  | awk '{total += $1} END {print total}'

    Guarda el primer resultado en directFilesExpectedCount y el segundo en directFilesExpectedBytes.

  3. Crea los módulos de datos

    Una aplicación pequeña puede utilizar un pack. Una carpeta grande debe repartirse entre varios. Cada archivo conserva la misma ruta relativa y una ruta no puede aparecer en dos packs.

    winlator/app/
├── miaplicacion_files_01/
│   ├── build.gradle
│   └── src/main/assets/
│       ├── MiAplicacion.exe
│       └── datos/parte-a.dat
└── miaplicacion_files_02/
    ├── build.gradle
    └── src/main/assets/
        └── datos/parte-b.dat

    Durante el desarrollo puedes usar enlaces simbólicos locales para evitar otra copia en el equipo de compilación. El AAB debe contener archivos normales y el árbol final en Android no debe contener enlaces simbólicos.

  4. Declara cada módulo

    El archivo build.gradle de cada pack cambia únicamente en packName. El modo on-demand permite que Win2APK mueva los archivos al prefijo y retire el origen cuando el backend del dispositivo ofrece STORAGE_FILES.

    plugins {
    id 'com.android.asset-pack'
}

assetPack {
    packName = 'miaplicacion_files_01'
    dynamicDelivery {
        deliveryType = 'on-demand'
    }
}

    Añade los módulos a winlator/app/settings.gradle:

    include ':app'
include ':miaplicacion_files_01'
include ':miaplicacion_files_02'
Esta es la parte que aún requiere preparación manual. Cambiar solo sourceFolder en el JSON no copia ni reparte la carpeta. Los nombres de assetPackNames, los módulos incluidos en settings.gradle y los directorios src/main/assets deben corresponder entre sí.

04 / Configuración

Define el nombre, el paquete, el icono y la ruta Windows

La fuente de configuración es config/win2apk.json. Gradle la copia al paquete durante la compilación.

Campos que debes sustituir

Parte del archivo actual y conserva las secciones de rootfs, pathRewriteAssets, inicio y runtime. El siguiente fragmento muestra los valores que cambian para cada aplicación, no un reemplazo completo del contrato.

{
  "app": {
    "folderName": "Mi Aplicacion",
    "sourceFolder": "/ruta/a/MiAplicacion",
    "assetPackNames": [
      "miaplicacion_files_01",
      "miaplicacion_files_02"
    ],
    "directFiles": true,
    "directFilesLinkMode": "move",
    "directFilesExpectedCount": 123,
    "directFilesExpectedBytes": 456789012,
    "windowsDirectory": "MiAplicacion",
    "windowsPath": "C:\\MiAplicacion",
    "executable": "MiAplicacion.exe"
  },
  "android": {
    "applicationIdBase": "com.tuestudio",
    "applicationId": "com.tuestudio.miaplicacion",
    "deriveApplicationIdFromFolder": true,
    "labelFromFolder": true,
    "label": "Mi Aplicacion",
    "iconPath": "/ruta/al/icono.svg",
    "iconBackgroundColor": "#1D5B45",
    "versionCode": 1,
    "versionName": "1.0"
  },
  "shortcut": {
    "name": "Mi Aplicacion",
    "desktopFile": "MiAplicacion.desktop",
    "execArguments": "",
    "forceFullscreen": false
  },
  "container": {
    "graphicsDriver": "auto",
    "dxwrapper": "auto",
    "cpuList": "auto",
    "cpuListWoW64": "auto"
  }
}
Lo que eliges Campo Efecto
Nombre visible app.folderName Define la etiqueta cuando labelFromFolder está activo y sirve como base del paquete automático.
Carpeta fuente app.sourceFolder Registra la entrada del empaquetado. El prototipo actual todavía necesita que prepares los módulos de datos.
Ejecutable app.executable Indica qué archivo abre Wine al tocar el icono.
Ruta en Windows windowsDirectory y windowsPath Ubica la carpeta dentro de la unidad C: del contenedor.
Nombre de paquete applicationIdBase, applicationId y deriveApplicationIdFromFolder Identifica la aplicación ante Android y determina si una compilación actualiza o instala otra app.
Icono android.iconPath Genera los recursos de launcher para densidades y formas compatibles.
Versión versionCode y versionName Controla actualizaciones y muestra una versión legible.

Cómo se obtiene el paquete automático

Con deriveApplicationIdFromFolder: true, Win2APK convierte el nombre a minúsculas, elimina caracteres que no sean letras o números y añade el resultado a applicationIdBase.

folderName: "Mi Juego 2"
applicationIdBase: "com.tuestudio"
resultado: "com.tuestudio.mijuego2"

Si el nombre normalizado empieza por un número, Win2APK añade app al principio. Para controlar el identificador directamente, usa deriveApplicationIdFromFolder: false y completa android.applicationId.

No cambies el paquete ni la firma durante una actualización. Android considera otro applicationId como otra aplicación. Si el paquete coincide pero el certificado cambia, devuelve INSTALL_FAILED_UPDATE_INCOMPATIBLE. Conserva el identificador y el keystore original, y aumenta versionCode.

Icono personalizado

Win2APK acepta una imagen rasterizada o SVG. Puedes guardar la ruta en el JSON o reemplazarla solo para una compilación:

bash gradlew :app:bundleDebug \
  -Pwin2apkIcon="/ruta/al/icono.svg" \
  --no-daemon --console=plain

El generador crea foreground, background, capa monocromática, variantes redonda y normal, y PNG por densidad. Consulta la documentación del icono para los detalles.

05 / Compilación

Genera el App Bundle con los datos declarados

Para una carpeta distribuida mediante asset packs, el artefacto principal es el AAB. El APK base por sí solo no contiene el payload completo.

  1. Entra al proyecto Android

    cd /ruta/al/repositorio/Win2APK/winlator/app

  2. Compila la variante debug

    bash gradlew :app:bundleDebug \
  --no-daemon \
  --console=plain

    Si quieres reemplazar el icono configurado para un único build, añade -Pwin2apkIcon="/ruta/al/icono.svg".

  3. Comprueba el archivo resultante

    app/build/outputs/bundle/debug/app-debug.aab

    El AAB es la entrada de bundletool o de una publicación compatible con App Bundles. No se instala directamente con adb install.

06 / Instalación Android

Convierte el AAB en un conjunto APKS e instálalo

La prueba local utiliza bundletool con --local-testing. El dispositivo debe estar conectado antes de construir el conjunto optimizado.

1. Identifica el dispositivo

adb devices -l

Copia el serial que aparece en la primera columna. En los comandos siguientes se representa como SERIAL.

2. Genera el conjunto APKS

cd /ruta/al/repositorio/Win2APK
mkdir -p winlator/app/app/build/outputs/apks

java -jar tools/bundletool-all-1.18.3.jar build-apks \
  --bundle=winlator/app/app/build/outputs/bundle/debug/app-debug.aab \
  --output=winlator/app/app/build/outputs/apks/miaplicacion-local-testing.apks \
  --local-testing \
  --connected-device \
  --device-id=SERIAL \
  --overwrite

Este comando produce un conjunto ajustado al dispositivo conectado. Repítelo para cada equipo de prueba. Para distribución general, conserva el AAB como fuente de publicación y deja que el canal de App Bundle genere los APK adecuados.

3. Instala base, configuraciones y asset packs

java -jar tools/bundletool-all-1.18.3.jar install-apks \
  --apks=winlator/app/app/build/outputs/apks/miaplicacion-local-testing.apks \
  --device-id=SERIAL

4. Abre la aplicación

Toca el icono en Android. En el primer inicio, Win2APK prepara el rootfs, obtiene los asset packs, valida cantidad y tamaño, mueve la carpeta al prefijo de Wine, crea el shortcut y abre el ejecutable configurado. El perfil gráfico queda en automático si graphicsDriver y dxwrapper usan el valor auto.

El primer inicio puede tardar. La duración depende del tamaño de la carpeta, almacenamiento y dispositivo. No cierres la aplicación mientras muestra la pantalla de preparación. Una prueba debe distinguir entre tiempo de instalación y tiempo hasta el primer frame de la aplicación Windows.

Instalación inicial frente a actualización

Caso Método Datos de la carpeta
Primera instalación con payload bundletool install-apks Instala base, splits y asset packs.
Actualización completa Nuevo APKS con mismo paquete y firma Android conserva los datos privados si la actualización es compatible.
Cambio solo en la APK base durante desarrollo adb install -r app-debug.apk Puede conservar el payload ya instalado, pero no sirve como primera instalación de los packs.

Para actualizaciones reproducibles, firma siempre con el mismo keystore. bundletool admite --ks=/ruta/segura/keystore.jks y --ks-key-alias=alias. Configura la misma identidad de firma en Gradle si también actualizarás la base con adb install -r. No guardes el archivo privado ni sus contraseñas en el repositorio.

07 / Resultado

Qué archivos obtienes y para qué sirve cada uno

Artefacto Ubicación habitual Uso
app-debug.aab app/build/outputs/bundle/debug/ Contiene la aplicación y referencia los asset packs. Es la entrada para bundletool o publicación AAB.
miaplicacion-local-testing.apks Ruta elegida en --output Archivo ZIP administrado por bundletool con APK base, splits y packs para el dispositivo.
app-debug.apk app/build/outputs/apk/debug/ APK base. Es útil para actualizar código durante pruebas, pero no representa una instalación completa con asset packs.
Aplicación instalada Almacenamiento privado de Android Incluye Winlator Core, el prefijo y la carpeta Windows movida desde los packs.
Sobre la frase “generar un APK”. Para carpetas grandes, el resultado instalable no es necesariamente un único archivo APK. El flujo probado genera un AAB y después un conjunto APKS. bundletool instala todas sus partes como una sola aplicación visible en Android.

Qué hace el usuario final

Después de la instalación, el usuario toca un icono. La interfaz general de Winlator permanece oculta, el sistema prepara el entorno y abre el ejecutable configurado. Cuando el programa Windows termina, la actividad Android puede cerrarse según startup.closeCoreWhenApplicationExits.

08 / Diagnóstico

Problemas frecuentes y su causa probable

La aplicación se instala, pero no aparece el juego o programa

Probablemente instalaste solo el APK base. Repite la instalación con el archivo APKS para incluir los asset packs. Confirma también que assetPackNames coincida con los módulos Gradle.

Android muestra INSTALL_FAILED_UPDATE_INCOMPATIBLE

La aplicación instalada y la nueva compilación tienen firmas distintas. Reconstruye con el mismo keystore. Desinstalar permitiría instalar la nueva firma, pero elimina los datos privados, por lo que no debe ser la primera opción si quieres conservar la carpeta.

Aparece Unable to create the configured container or shortcut

Revisa windowsDirectory, windowsPath, executable, nombres de packs y conteos esperados. El ejecutable debe existir dentro del árbol movido y la ruta del shortcut debe apuntar al mismo directorio.

bundletool falla con un pack demasiado grande

Divide la carpeta entre varios packs y conserva rutas relativas únicas. Cuphead necesitó cinco módulos de archivos en la variante actual. Ese número es un ejemplo medido, no una regla para todas las aplicaciones.

El icono anterior sigue visible

Confirma que iconPath exista, aumenta versionCode y verifica que instalaste la nueva base con la misma firma. Algunos launchers conservan caché durante un tiempo.

El ejecutable abre, pero los gráficos fallan

Mantén graphicsDriver: "auto" y dxwrapper: "auto" para usar el perfil por dispositivo. Si la aplicación exige otra API gráfica, versión de DXVK o componentes de Windows, registra una prueba separada. Un resultado en un modelo no demuestra compatibilidad con todos.

Android advierte que la aplicación fue creada para una versión anterior

La variante actual conserva targetSdkVersion=28 porque el entorno ejecuta Box64 y Wine desde el almacenamiento privado de la aplicación. Subir el target sin rediseñar esa ruta produjo un bloqueo SELinux en las pruebas del proyecto. La advertencia es una limitación conocida del prototipo para Android moderno.

Comandos básicos de diagnóstico

adb -s SERIAL shell dumpsys package NOMBRE_DEL_PAQUETE
adb -s SERIAL shell pidof NOMBRE_DEL_PAQUETE
adb -s SERIAL logcat | rg 'Win2APK|AndroidRuntime|FATAL EXCEPTION'

Lista de control antes de construir otro paquete

  • La carpeta contiene el ejecutable final y todos sus recursos.
  • Los módulos de asset pack contienen cada archivo una sola vez y conservan su ruta relativa.
  • Los nombres de los módulos coinciden con assetPackNames y settings.gradle.
  • El conteo y tamaño esperado corresponden a la carpeta seleccionada.
  • windowsDirectory, windowsPath y executable describen la misma ubicación.
  • El nombre de paquete es válido y permanecerá estable en futuras versiones.
  • El icono existe y tienes permiso para usarlo.
  • El versionCode es mayor que el de la versión que vas a actualizar.
  • La compilación y bundletool utilizan el mismo keystore de las versiones anteriores.
  • La prueba se hará primero en un dispositivo y conservará logs antes de ampliar la conclusión.
